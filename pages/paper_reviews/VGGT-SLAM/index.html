Abstract

우리는 이런 연구를 했어요

VGGT-SLAM

  • uncalibrated monocular camera + VGGT

    → submap 형성

  • 만들어지는 submap들을 점진적, 전역적으로 정렬

    → dense RGB SLAM

VGGT

  • feed-foward를 통해 scene reconstruction을 수행하는 접근법

관련 연구는 이랬어요
  • similarity transform을 통해 submap 정렬 (e.g. 이동, 회전, 크기 변환)

    → uncalibrated camera에서는 부적합

이러한 문제점이 있었어요

재구성 모호성

  • 카메라 움직임이나 장면 구조에 대한 어떠한 가정도 없는 uncalibrated camera들이 주어질 경우, 장면은 실제 기하와 동치인 15자유도의 투영 변환(projective transformation)까지밖에 복원될 수 없음

    → SL(4) manifold 상에서 최적화를 수행하여, 잠재적인 loop closure 제약을 고려하면서 연속적인 서브맵들 사이의 15자유도 homography 변환을 추정하고, 이를 통해 일관된 장면 재구성을 달성

이런 성과를 이뤄냈어요

장기 비디오 시퀀스 매핑 성능을 향상시킴

→ VGGT의 높은 GPU 요구사항으로는 실현 불가능

Introduction

SLAM 이란?
  • 3D scene reconstruction
  • 6-DOF camera pose estimation

    → 위 2가지 task를 동시에 수행하는 것

기존 패러다임
  • multi-view geometry constraints
  • data association
  • backend optimization (e.g. bundle adjustment)

    → 위 과정을 조합한 복잡한 SLAM 파이프라인 구성

새로운 패러다임
  • uncalibrated image를 입력받아 feed-forward network를 거쳐 point cloud reconstruction을 수행

    → 구조가 매우 단순해짐

관련 연구들

DUSt3R

  • 입력: 이미지 쌍
  • 출력: 두 프레임의 dense point cloud
  • 특징
    • 두 프레임의 point cloud를 첫 번째 카메라의 좌표계(reference frame) 기준으로 추정

      → dense scene reconstruction 수행

    • 3-point RANSAC solver

      → camera pose 쉽게 추정 가능

  • 한계
    • 두 장의 이미지만 입력으로 처리 가능

VGGT

  • 입력: 임의 개수의 이미지들
  • 출력
    • dense point clouds
  • 특징
    • 출력으로 dense point clouds 외에도 depth maps, feature tracks, camera poses, camera intrinsics 등의 여러 3D quantities 출력 가능
  • 한계
    • GPU 메모리 제한 때문에 처리 가능한 프레임 수가 제한됨

문제점 1 - GPU 메모리 사용량

VGGT

  • 입력 프레임에 비례하여 GPU 메모리 사용량도 그만큼 증가

    (NVIDIA GeForce RTX 4090 24 GB 환경에서 60프레임이 최대)

해결 방법

Submap 기반 접근

  1. VGGT를 이용해 여러 submap 생성
  1. 각 submap은 최소 1개의 overlapping frame을 공유
  1. submap 간 alignment 수행
    • VGGT가 추정한 pose 정보 활용
    • rotation + translation 정렬
    • scale parameter 추정

→ 즉, submap 사이의 Sim(3) transformation 추정

Sim(3) 최적화는 실제로 많은 경우에서 좋은 reconstruction 결과를 보여줌

문제점 2 - Projective Ambiguity

하지만 실험에서 Projective Ambiguity가 관측됌

특히 다음 상황에서 문제가 발생

  • uncalibrated cameras 사용
  • VGGT feed-forward reconstruction
  • frame 간 disparity가 작은 경우

    → projective ambiguity 발생

중요한 점으로 Sim(3)는 아래 자유도만 포함

  • rotation
  • translation
  • scale

하지만 projective ambiguity는 추가적으로

  • shear
  • stretch
  • perspective distortion

과 같은 자유도를 포함

→ 따라서 similarity transformation만으로는 이 ambiguity를 완전히 해결할 수 없음

해결 방법

projective ambiguity를 이해하기 위해 저자들은 고전적인 컴퓨터 비전 이론으로 돌아감

고전 이론

  • projective reconstruction → metric reconstruction 변환

    → 4×4 homography matrix를 계산해야 함

  • 4×4 homography matrix
    • Special Linear Group SL(4)에 속함

      → Lie group 구조를 가짐

제안하는 접근법

  • SL(4) manifold 위에서 최적화되는 factor graph로 submap alignment 문제를 해결하자
    • 아래 2개의 요소를 함께 이용하여 임의의 수의 submap을 전역적으로 정렬
      • 연속적인 submap 간 relative homography
      • loop closure constraint

Contribution
  • VGGT 기반 최초의 SLAM 시스템
  • projective constraint를 도입하여 Projective Ambiguity 해결
  • SL(4) 기반 Factor Graph 제안하여 similarity transformation이 부족한 상황을 다룰 수 있는 원칙적인 프레임워크 제공
  • SOTA learning-based SLAM과 비슷하거나 더 좋은 성능을 보임

Review: VGGT

VGGT

과정

  1. wˉ\bar{w}wˉ﻿개의 이미지 입력 받음
  1. 파인튜닝된 DINO backbone으로 토큰화
  1. Alternating-Attention 적용
  1. 출력
    • camera head에서 출력된 토큰 기반으로 intrinsics과 camera poses 예측
    • DPT(Dense Prediction Transformer) head에서 각 이미지에 대한 dense depth maps 출력
    • point tracking을 위한 dense features

    → 각 출력에는 신뢰도(confidence) 값이 함께 제공됨

특징

  • VGGT의 출력은 항상 첫 번째 카메라 좌표계 기준으로 생성

VGGT-SLAM
  • dense depth maps
  • confidence score maps

각 이미지 I\mathcal{I}I﻿에 대한 출력을 submap S\mathcal{S}S﻿로 정의

→ 이는 pose graph optimization 단계에서 하나의 노드로 사용됌

3D point DPT head를 그대로 사용하지 않음

  • Wang et al. 에게 관찰된 바에 따르면, camera head에서 얻은 투영(projection) 행렬을 이용해 깊이 맵 D\text{D}D﻿를 역투영하면 더 정확한 point cloud 를 얻을 수 있다고 함

    → 이렇게 생성된 dense point cloud는 첫 번째 카메라 좌표계를 기준으로 정의되며, XS\text{X}^{\mathcal{S}}XS﻿라고 부름

  • unreliable points를 필터링하기 위해, 전체 confidence C\mathcal{C}C﻿의 평균인 τconf\tau_{\text{conf}}τconf​﻿를 구하고, 이보다 작은 값을 가진 points를 pruning함

VGGT-SLAM

Incremental submap-based keyframe selection and generation

연속적으로 입력되는 이미지들로부터 incremental하게 submap을 구성하고, 각 submap 내에서 keyframe을 선택하고 구성하는 방법을 설명

  • Ilatest\mathcal{I}_\text{latest}Ilatest​﻿: image set
  1. 하나의 이미지를 keyframe으로 선정한다.
  1. 현재 이미지와 이전 keyframe 사이의 disparity가 user-defined threshold τdisparity\tau_\text{disparity}τdisparity​﻿보다 클 경우, 해당 이미지를 새로운 keyframe으로 선택한다. (이때 disparity는 Lucas-Kanade 방법을 이용해 추정한다.)

VGGT는 learned priors를 기반으로 monocular depth를 추정할 수 있는 능력을 가지고 있음

→ 그러나 충분한 disparity를 가진 프레임을 활용하면, multi-view 정보를 추가로 활용할 수 있어 relative depth estimation 성능이 향상되고, 동시에 처리해야 할 프레임 수를 줄일 수 있음

만약 충분히 큰 disparity가 추정되면 현재 프레임을 keyframe으로 지정하고, Ilatest\mathcal{I}_\text{latest}Ilatest​﻿에 추가

→ 해당 과정은 Ilatest\mathcal{I}_\text{latest}Ilatest​﻿가 미리 설정한 한계 www﻿에 도달할 때 까지 반복

각 submap과 연관된 이미지 집합은 두 개의 추가 프레임 집합을 이어 붙여 구성됨

첫 번째 집합은 단일 프레임으로 구성되며, 이는 이전 submap의 마지막 non-loop-closure 프레임으로 선택된 프레임이며 Mprior\text{M}_\text{prior}Mprior​﻿으로 표기함

또한 loop closure를 위해 사용할 wloopw_\text{loop}wloop​﻿개 까지의 프레임이 이미지 집합의 끝에 추가될 수 있음

따라서, submap을 위한 최종 이미지 집합은 아래와 같이 구성됌

해당 이미지 집합 Ilatest\mathcal{I}_\text{latest}Ilatest​﻿은 이후 VGGT에 입력되어 submap Slatest\mathcal{S}_\text{latest}Slatest​﻿을 형성

Local submap alignment addressing projective ambiguity

서로 겹치는 영역을 가지는 두 submap Si\mathcal{S}_iSi​﻿, Sj\mathcal{S}_jSj​﻿ 는 위에서 설명한 방식으로 생성

각 submap은 각자의 local submap frame에서 정의된 point cloud XSi\bold{X}^{\mathcal{S}_i}XSi​﻿, XSj\bold{X}^{\mathcal{S}_j}XSj​﻿를 가짐

→ 저자의 목표는 두 submap을 정렬하는 변환 Hji∈R4×4\bold{H}_j^i\in\R^{4\times4}Hji​∈R4×4﻿을 구하는 것

해당 변환은 모든 noise-free 대응점 XSi,XSj∈R3\bold{X}^{\mathcal{S}_i},\bold{X}^{\mathcal{S}_j}\in \R^3XSi​,XSj​∈R3﻿에 대해 아래 관계를 만족

여기서 4×4 homography matrix와 곱해질 때, XS\bold{X}^\mathcal{S}XS﻿는 homogeneous coordinates로 표현된다고 가정

전형적인 3D point cloud alignment 문제 (예: LIDAR SLAM)에서는

  • HHH﻿는 SE(3)\text{SE}(3)SE(3)﻿ 상의 변환으로, translation과 rotation을 나타냄
  • 만약 point cloud 사이에 scale 차이가 존재한다면, H\bold{H}H﻿는 similarity transformation group인 Sim(3)\text{Sim(3)}Sim(3)﻿에 속함

→ 하지만 여기서는 XS\bold{X}^\mathcal{S}XS﻿가 uncalibrated camera로부터 생성된 point cloud이므로, 일반적인 point cloud와는 다름

따라서 Projective Reconstruction Theorem을 고려해야 함

  • uncalibrated camera로 촬영된 두 이미지 사이의 대응점들이 fundamental matrix를 유일하게 결정할 수 있다면, 해당 대응점들을 이용해 3D 점들을 최대 15 자유도(15-DOF)의 homography transformation까지의 모호성을 가진 상태로 재구성할 수 있음

    → 이 변환은 대응하는 모든 점들에 대해 동일하게 적용됌

    (단, 두 카메라 중심을 연결하는 직선 위에 있는 점들은 예외인데, 이 점들은 유일하게 재구성될 수 없음)

  • 다중 시점(두 카메라 이상) reconstruction에 적용됌

대부분의 경우에 uncalibrated camera 집합을 이용하여 계산된 reconstruction은 projective transformation H\bold{H}H﻿로 metrically correct하게 만들어진 reconstruction과 다름

matrix H\bold{H}H﻿

  • 15DOF를 가짐
  • special linear group인 SL(4)\text{SL(4)}SL(4)﻿에 속함
    • SL(4)\text{SL(4)}SL(4)﻿는 unit determinant를 가지는 실수값으로 구성된 모든 4x4 행렬을 포함

      → 이는 image warping 같은 planar computer vision task에서 흔히 사용되는 8DOF homography matrix와는 다름 (SL(3)\text{SL(3)}SL(3)﻿에 속함)

reconstruction은 scene prior가 이용가능할 때, affine reconstruction으로 변환될 수 있으며, 예를들어 점들이 평행선 위에 놓여있는 경우가 있다.

더 나아가, 장면에 있는 선들이 직교한다는 prior가 알려져 있을 경우, reconstruction은 metric reconstruction으로 변환될 수 있다. (해당 경우에 실제 유클리디안 reconstruciton과 similarity transform만큼의 차이만 발생하게 된다.)

VGGT

  • metric reconstruction을 잠재적으로 추정하기 위해 learned scene prior를 사용 가능
  • 하지만 scene priors의 추정이 unreliable한 대부분의 일반적인 경우에는 reconstruction이 projective ambiguity에 의해 달라지며, 이를 복원하기 위해 15-DOF homography matrix를 필요로 함

    → 해당 homography 추정할 예정

동일한 프레임을 공유하는 submap 형성으로, association을 추정할 필요 없이 correspondence의 dense set을 가지기 때문에, H\bold{H}H﻿를 구하는 데에 이례적인(atypical) 이점을 가진다.

잘 알려진 direct reconstruction method에 의해, (1)번 수식의 최적의 homography는 closed form으로 구해질 수 있으며, 아래 homogeneous linear system의 soluton이 된다.

  • h\bold{h}h﻿는 R16\R^{16}R16﻿에 속하며, homography의 flatten parameter를 포함
  • Ak\bold{A}_kAk​﻿는 3차원 점들의 특정 쌍을 위한 제약(constraints)를 포함

이를 풀기 위한 최소한의 solution은 적어도 5개의 점들을 필요로 하며, VGGT의 부정확한 깊이 측정에 강건한 시스템을 위해 5-point solver RANSAC을 사용해 (2)번 수식을 푼다.

homography matrix는 scale에 맞게 추정되기 때문에, determinant의 네제곱근으로 scaling하여 determinant가 통일되고, 최종 matrix가 SL(4)\text{SL(4)}SL(4)﻿에 속하게 된다.

Limitations

  • planar points에 대한 homography 추정이 어려움
  • outlier에 취약
    • 5-point RANSAC으로 해결을 시도해봤지만, 높은 outlier 비율 및 adversarial outliers가 부정확한 homography 추정을 일으킴
  • MASt3R-SLAM에서 ray 기반 matching은 depth 측정에서 강건함을 제공하며, 비슷한 방법이 homography 추정을 잠재적으로 보완 가능
  • 15 DOF의 scene drift 초래
    • 부정확한 relative homography 추정이나 loop closure간의 장기간 공백이 scale, rotation, translation drift 뿐만 아니라, scene perspective에서도 drift가 발생함

      → 이는 SL(4) 기반 SLAM의 추가적인 최적화는 중요한 향후 연구 주제
