DynaSLAM: Tracking, Mapping and Inpainting in Dynamic Scenes

키워드
  • a priori dynamic object

    → 흔히 우리가 그렇게 생각하는 동적 객체 (즉, 사람이나 동물 등 우리가 움직인다고 생각하는 객체)

요약

현 시점(2018.08) 아래 사항을 고려하는 SLAM 알고리즘이 없음

  1. 동적 객체 탐지 방법
    1. tracking이 동적 객체의 matched point를 사용하지 않게끔
    1. 동적 객체를 3D map에서 제외하게끔
  1. 움직이는 물체에 의해 일시적인 가려진 부분을 채우는 방법

그래서 우리가 만듦

  • ORB-SLAM2 기반으로 tracking 정확도, 맵 재사용성 관점에서 평가
    • Mono, Stereo
      • CNN 기반 pixel-wise segmentation
    • RGB-D
      • MVG/딥러닝 기반 동적 객체 제거 및 인페인팅
관련 연구
  • feature point projection
  • 3d object tracking
  • scene flow with Stereo Camera
  • RGB optical flow
  • difference of depth
  • difference of intensity
  • moving object detection (움직이는 정적 객체는 못잡음)
  • movable object detection

공통점

  • feature based
  • static information만 사용 (dynamic information은 제거)

시스템

Mono, Stereo

  • CNN 기반 동적 객체 segmentation
    • 동적 객체의 keypoint가 검출되지 않게끔함

RGB-D

  • CNN 기반 동적 객체 segmentation을 refine
  • 대부분 시간동안 움직이지 않는 동적 객체를 새롭게 labeling

    → 이를 위해 camera pose가 필요하며, 이는 low-cost tracking으로 얻을 수 있음

  • CNN 기반 segmentation에서 검출이 되지 않은 동적 객체 클래스에 대해 MVG로 검출

    → 하지만 정확도가 낮아짐

Segmentation Potentially Dynamic object
  • CNN 기반 segmentation으로 동적 객체 탐지

    → (그 당시) SOTA 2D Segmentation model인 Mask R-CNN

  • 학습용 데이터셋
    • MS COCO (여기에 없는 동적 객체를 포함하는 데이터를 따로 fine tuning해서 사용 가능)

Low-Cost Tracking
  • 보통 카메라 포즈는 이미지의 정적 부분만을 이용해서 tracking함

    → 동적 객체의 윤곽은 너무 변화가 큼

  • Tracking은 ORB-SLAM2에서 가져옴
    • 맵의 특징을 이미지에 투영시켜, 대응하는 픽셀간의 reprojection error를 줄여서 카메라 포즈 최적화

Mask R-CNN Segmentation & Multi-view Geometry
  • Segmentation만으로는 a priori 객체가 아닌 움직이는 물체는 탐지 못함

    → 예를들어 사람이 옮기고 있는 책, 가구의 (장기)위치 변화 등

  • 현재 keyframe 기준 이전 overlapping frame 5개를 선정
    • 기준: 현재 keyframe을 기준으로 거리와 회전을 고려하여 가장 많이 겹치는 keyframe

      → 5개인 이유는 동적 객체 탐지에서 정확도와 연산 비용에서 타협을 본 것임

    • 가정
      • x′x'x′﻿: 이전 5개의 keyframe의 keypoint xxx﻿들을 현재 keyframe으로 투영한 것

        (여기서 keypoint는 ORB-SLAM2의 feature extractor를 통해 얻음)

      • zprojz_{proj}zproj​﻿: 카메라 움직임을 기반으로 투영된 x′x'x′﻿의 depth값을 계산한 것

        → 즉 x′x'x′﻿과 3D Point XXX﻿와의 거리

      • z′z'z′﻿: depth sensor로 측정한 값
    • 동적 객체 탐지
      • angle 기반 탐지
        • α\alphaα﻿: z′z'z′﻿와 zprojz_{proj}zproj​﻿ 사이의 각도

          → 해당 각도가 30°30\degree30°﻿ 이상이면 동적 객체로 판단 (TUM dataset으로 증명함)

      • depth 기반 탐지
        • Δz=zproj−z′\Delta z= z_{proj}-z'Δz=zproj​−z′﻿

          → Δz\Delta zΔz﻿가 threshold τz\tau_{z}τz​﻿를 초과하면 동적 객체로 판단

          (threshold τz\tau_{z}τz​﻿는 TUM dataset에서 바꿔가면서 실험한 결과 0.7×Precision+0.3×Recall0.7\times\text{Precision}+0.3\times\text{Recall}0.7×Precision+0.3×Recall﻿을 최대화한 τz=0.4\tau_{z}=0.4τz​=0.4﻿로 설정)

    • 특이사항
      • 동적 객체의 경계에 있는 keypoint 주변으로 patch를 두어, 해당 patch의 depth값 분포의 분산이 크다면 이는 정적 객체로 봄

  • Multi-view Geometry + Deep Learning
    • Geometry Based: 초기화 문제가 있지만, 기하학적으로 정확한 위치관계 파악 가능
    • Deep Learning Based: labeling이 안된 움직이는 정적 객체를 탐지하지 못하지만, 초기화 과정 없이 단일 이미지에서 동적 객체를 탐지 가능

      ⇒ Geometry Based + Deep Learning Based

      서로의 약점을 보완

Tracking & Mapping
  • 전처리
    • segmentation mask로 RGB image를 static only image로 만든 후, 이전에 언급한 동적 객체의 경계 부분에 생기는 keypoint를 제거해줘야 함

Background Inpainting

방법

  • 현재 keyframe에서 동적 객체의 빈 부분에, 이전 keyframe들의 RGB & depth 정보를 투영

특이사항

  • 그럼에도 inpainting이 적용 안된 부분들
    • 이전 keyframe들 중에서 해당 빈 부분에 대응하는 부분이 없는 경우
    • 해당 빈 부분에 대해 유효한 depth 정보가 없는 경우

      ⇒ 이러한 경우들은 더 유연한 인페이팅 방법이 필요

  • 이렇게 inpainting을 진행하여 생성된 synthetic frame에 대해, 정적 환경을 가정하는 다른 SLAM 시스템에서도 사용 가능함

평가
  • 데이터셋 (TUM-RGBD)
    • 종류
      • sitting (s)sitting\ (s)sitting (s)﻿
      • walking (w)walking\ (w)walking (w)﻿
    • 시퀀스
      • halfsphere (1m 지름을 가진 반구 형태의 궤적으로 움직이는 카메라)
      • xyz (x, y, z 축을 따라 움직이는 카메라)
      • rpy (roll, pitch, yaw 축을 기준으로 움직이는 카메라)
      • static (움직이지 않는 카메라)
  • 평가 방식
    • ORB-SLAM2와 비슷하게 non-deterministic effect를 고려함

      → 다른 점은 각 시퀀스를 10번 돌려 중앙값으로 선정 (ORB-SLAM2는 5번)

  • 평가 지표
    • AT-RMSE (Absolute Trajectory Root Mean Squared Error)

  • 결과
    • 모델 ablation study
      • DynaSLAM(N): 딥러닝 기반 동적 객체 탐지
      • DynaSLAM(G): 기하 기반 동적 객체 탐지
      • DynaSLAM(N+G): 딥러닝, 기하 기반 동적 객체 탐지
      • DynaSLAM(N+G+BI): 딥러닝, 기하 기반 동적 객체 탐지 + 배경 인페인팅

        ⇒ 결과적으로는 DynaSLAM(N+G)이 대부분의 경우에서 가장 좋은 성능을 보임\

      • 특이사항
        • DynaSLAM(N+G+BI)
          • camera localization 이전에 Background Inpainting 과정이 오히려 정확도를 줄임

            → 특히 rpy나 halfsphere 같이 카메라 포즈 추정이 어려운 시퀀스에 대해서 부정확한 Background Reconstruction으로 인해 (N+G) 모델보다 낮은 정확도를 보임

            (따라서 Background Inpainting은 Tracking stage 이후에 진행되어야 함)

    • ORB-SLAM2와 비교
      • high dynamic sequence에서는 ORB-SLAM2의 성능을 능가
      • 하지만 오히려 sxyzs_{xyz}sxyz​﻿와 같이 움직임이 적은 데이터셋에서는 오히려 성능이 떨어짐

    • 다른 SOTA RGB-D SLAM과의 비교

    • ORB-SLAM과의 Monocular System 비교
      • DynaSLAM이 ORB-SLAM이 전체적으로 정확도가 낮은데, 이는 DynaSLAM의 backbone인 ORB-SLAM2와 초기화 방식이 다르기 때문

        → ORB-SLAM2가 ORB-SLAM보다 초기화가 더 빠르기 때문에, 초반에 동적 객체에 더 많은 영향을 받기 때문이라고 함

  • 데이터셋 (KITTI)
    • 평가 지표
      • AT-RMSE (Absolute Trajectory Root Mean Squared Error)
      • RPE (Relative Pose Error)
      • RRE (Relative Rotation Error)
    • 결과
      • ORB-SLAM2와 비교
        • 동적 객체가 모두 움직이는 시퀀스(e.g. KITTI 01, KITTI 04)에 대해, 해당 동적 객체에 대한 feature를 쓰지 않았을 때 tracking 성능이 향상됌
        • 차량이 주차되어 있는 장면이 포함된 시퀀스(e.g. KITTI 00, KITTI 02, KITTI 06)는 거리가 먼 곳이나, 질감이 적은 지역에서 keypoint가 잡혀서 정확도가 떨어짐
        • 맵이 정적 구역으로만 구성되기 때문에, loop closure와 relocalization algorithms은 더 강건하게 동작

Timing Analysis
  • Multi-view Geometry는 대부분 region growth 알고리즘으로 인해 생기는 delay임
  • Background Inpainting도 상당히 시간을 잡아먹기 때문에, 이 또한 Tracking 뒷단으로 넘겨야 하는 이유 중 하나임
