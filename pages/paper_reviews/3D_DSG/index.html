논문 스터디

Abstract

본 논문에서는 크게 3가지의 기여를 진행하였다.

  1. 기존 Scene Graph를 Dynamic Scene Graph(DSG)로 확장하여 움직이는 agents를 처리할 수 있고, planning과 decision-making도 가능하게 한다.
  1. visual inertial data로부터 DSG를 생성하는 완전 자동화 Spatial PerceptIon eNgine(SPIN)을 제공하며, visual-inertial SLAM과 dense human mesh tracking을 결합한 최초의 논문을 제공한다.
  1. 사실적인 유니티(Unity)기반 시뮬레이터 환경에서 제안하는 SPIN을 평가한다.

3D DYNAMIC SCENE GRAPHS

  • 개념
    • DSG = Layered Directed Graph
    • 5 layers
      • Layer 1: Metric-Semantic Mesh
      • Layer 2: Objects and Agents
      • Layer 3: Places and Structures
      • Layer 4: Rooms
      • Layer 5: Building

  • 구성
    • Node(노드): 공간 개념 (mesh, object, place, room, human…)
    • Edge(엣지): 공간적(spatial) + 시간적(temporal) 관계

Layer 1: Metric-Semantic Mesh

Node: 3D points

  • 3D position
  • normal
  • RGB color
  • panoptic semantic label

    → 해당 노드 3개를 잇는 Edge가 하나의 3D Mesh 형성

    • 해당 Mesh는 환경의 모든 정적 객체를 포함 (동적 객체는 다른 별도의 구조 사용)

Layer 2: Objects and Agents

Node: objects

  • 정적 비구조물(e.g. 의자, 책상 등)을 의미
    • 구조물(e.g. 천장, 바닥, 벽 등)은 해당 layer에서 모델링 되지 않음
  • 속성
    1. 3D object pose
    1. bounding box
    1. semantic class

Edge: objects

  • objects간의 relation을 의미
    • co-visibility
    • relative size
    • distance
    • contact (접촉)

→ 각 object node는 Layer 1의 mesh와 직접 연결됨

Node: Agents

  • 동적 개체 (e.g. 사람, 로봇 등)
  • 속성
    1. 시간에 따라 개체의 궤적을 보여주는 3D pose graph
      • 여기서 pose graph는 시간대별 개체의 3D pose를 측정한 것
    1. 개체의 비강체(non-rigid) 형태를 보여주는 mesh 모델
    1. a semantic class(e.g. robot(자기 자신), human)

Edge: Agents

  • 각 시간대별 개체의 상대적 움직임을 의미

→ 사람을 “dynamic point”가 아니라 시간적으로 연속된 3D mesh로 다룸

Layer 3: Places and Structures

Node: Places

  • 구성
    • Node: free space를 대표
    • Edge: traversability(횡단 가능성)
    • Attributes: 3D position, semantic class, obstacle-free bounding box
  • 특징
    • Places의 Node와 Edge는 topological map을 형성하여, path planning에 사용 가능
    • Layer 2의 agents나 Layer 4의 rooms과도 연결됨

Node: Structures

  • 구성
    • Node: 구조적 요소(e.g. 벽, 바닥, 천장 등)를 의미
      • Attributes: 3D pose, bounding box, semantic class
    • Edge: relationship
  • 특징
    • Layer 2의 object와 연결됨 (e.g. “frame(object) is hung on(relationship) a wall(structure)”)

Layer 4: Rooms
  • 구성
    • Node: 방, 복도, 홀을 나타냄
      • Attributes: 3D pose, bounding box, semantic class (e.g. 부엌, 식당, 복도 등)
    • Edge: 두 개의 방이 인접하다면 연결 (e.g. 두 방 사이의 문)
  • 특징
    • Layer 3의 places에 연결됨 (rooms 내부에 속한 places)
    • Layer 5의 building과 연결됨 (rooms는 building에 속해있음)

Layer 5: Building
  • 구성
    • Node: 단일 건물
      • Attributes: 3D pose, bounding box, semantic class (e.g. 사옥, 빌라, 아파트 등)
  • 특징
    • 건물 내부의 모든 room들과 연결됨

Composition and Queries

위에서 설계된 Node와 Edge는 아래의 특징을 가진다.

Planning Queries

  • Semantic Node: “빨간 컵을 들어서 식당에 있는 책상에 놔줘”와 같은 고수준의 명령어를 받아 planning 수행
  • Geometry Node, Edges: motion planning, collision checking에 사용

Composition of DSGs

  • 건물과 방 사이에 “Level” 층을 새롭게 추가 가능
  • 건물 → 도시 → 이웃 단위로 확장 가능

SPATIAL PERCEPTION ENGINE: BUILDING A 3D DSGs FROM SENSOR DATA

SPIN(Spatial PerceptIon eNgine)은 센서 데이터를 입력 받고, DSG node와 edge를 생성한다.

센서 데이터는 아래와 같이 구성된다.

  • stereo camera + IMU

본 연구에서 metric-sementic mesh와 agent는 실시간으로 생성되고, 나머지 노드들은 후처리로 자동 생성된다.

아래는 각 세션별 과정을 간략히 설명한다.

  • Section A: 센서 데이터로부터 metric-semantic mesh와 agent node를 얻는 방법
  • Section B: object를 분할하고 위치추정 하는 방법
  • Section C: places, structures, rooms를 파싱하는 방법

A. From Visual-Inertial data to Mesh and Agents

Mesh

  • Kimera를 사용
    모듈역할
    Kimera-VIOVisual-Inertial Odometry
    Kimera-RPGORobust Pose Graph Optimization
    Kimera-MesherIncremental 3D Mesh
    Kimera-SemanticsPanoptic Semantic Mesh

Robot Node

  • 로봇(자기 자신)도 Agent로 취급
  • Kimera-RPGO에서 나오는 pose graph = robot node

혼잡 환경 대응을 위한 개선

  • Kimera에서 아래 2가지를 교체
    • IMU-aware optical flow
      • feature 이동을 IMU 회전으로 예측
      • 동적 객체가 많아도 feature tracking 안정
    • 2-point RANSAC
      • IMU rotation을 이미 알고 있다는 가정
      • correspondence 검증이 훨씬 강건

Human Node

  • 기존 접근
    • 동적 객체를 3차원 점이나 포즈로 인식

→ DSG

  • 동적 객체를 시간에 따라 변하는 dense 3D mesh model로 인식

→ human node를 만들기 위해서 SPIN은 카메라 이미지에서 사람을 탐지(detect)하고 형태를 추정(shape estimation)하여 추적(tracking)할 수 있어야 함

[ Shape Estimation ]

  • Kolotouros et al.의 Graph-CNN 기반 접근법을 통해 3D SMPL 추정
    • 추정된 weak perspective camera model을 PnP를 이용해 full pose로 변환

[ Tracking ]

  • Human Tracking을 위해서, SPIN은 시간별로 사람의 몸통(torso)에 노드를 할당하여 pose graph를 형성한다
    • 각 시간별 pose 사이의 prior factor
      • zero-velocity prior (연속성)
      • detection prior (관측)

[ Data Association ]

  • 사람 여러 명 + occlusion → 부정확한 포즈 생성❗️
  • 해결 방법
    1. Robustness
      • detection
        • bbox 너무 작으면 제거
        • 화면 가장자리면 제거
      • ttt﻿의 human mesh가 t−1t-1t−1﻿의 human mesh와 “consistent” 할 때만 측정
    1. Joint Motion Consistency
      • t−1t-1t−1﻿ skeleton vs ttt﻿ skeleton 비교
        • 물리적으로 나올 수 있는 관절의 움직임인지 확인
      • 각 joint 이동 거리 제한 (1초에 3m 이내)

B. From Mesh to Objects

SPIN은 Kimera로 얻은 metric-semantic mesh에서 정적 객체를 추출한다.

저자들은 각 객체 클래스에 대한 CAD 카탈로그를 제공하며, 해당 Mesh-Objects 추출 과정은 아래와 같이 2가지 경우로 나뉜다.

  • Objects with Unknow Shpae (모양이 알려지지 않은 객체)
  • Objects with Known Shpae (모양이 알려진 객체)

[ Objects with Unknown Shape ]

  • 과정
    1. Mesh Exacting
      • Kimera에서 제공하는 metric-semantic mesh에서 특정 클래스에 속하는 메쉬 일부분 잡기
        • 해당 mesh는 하나의 클래스지만 여러 instance들이 포함되어 있을 수 있음
    1. Mesh Clustering & Axes Aligning
      • mesh에 Euclidean clustering을 적용하여, 세부 instance cluster 형성
      • 각 cluster의 centroid에 대해 world 좌표계에 맞춘 canonical orientation을 적용
    1. Bounding Box
      • 정렬된 축을 기준으로 bounding box 생성

[ Objects with Known Shape ]

  • 과정
    1. Keypoint Extraction
      • CAD 모델과 Kimera에서 얻은 Mesh에 대해 각각 3D Keypoint 추출
      • 3D Pointcloud 변환 및 3D Harris Corner 알고리즘 사용
    1. Keypoint Matching
      • 해당 과정에서 outlier가 많이 생김
    1. Registration
      • TEASER++
        • 강건한 정합을 위해 사용한 오픈소스

C. From Mesh to Places, Structures, and Rooms

여기서는 기존 Kimera mesh에서 places, structures, rooms를 파싱하는 방법을 설명한다.

Places (장소)

  • Kimera는 Voxblox를 사용하여 전역 메시(global mesh)와 ESDF(Euclidean Signed Distance Field)생성한다.
    • SPIN은 해당 ESDF에서 topological graph를 얻음
      • Node: 자유 공간(free space)을 희소(sparse)하게 샘플링
      • Edge: 두 노드 사이의 직선 이동 가능성(straight-line traversability)을 나타냄

      → topology graph를 이용해 장소와 장소의 topology를 바로 추출

이후, 각 객체(object)와 에이전트(agent) 위치를 가장 가까운 장소와 연결하여 근접 관계(proximity relation)를 모델링

Structures (구조물)

  • Kimera의 시맨틱 메시에는 이미 벽(walls), 바닥(ground floor), 천장(ceiling)에 대한 라벨이 있음

    → 따라서 위 세 가지 구조 요소를 분리하는 것은 간단

    • 각 구조 요소에 대해:
      1. Centroid 계산
      1. Canonical Orientation 적용 (world 좌표계에 맞춤)
      1. Axis-aligned Bounding Box 계산

      → [ Objects with Unknown Shape ] 과정과 동일

Rooms (방)

  • 일반적으로 층(plan) 계산은 어려움

    → 하지만 SPIN에서는 2가지 조건 덕분에 간단하고 효과적인 방 분할 가능:

    1. 3D ESDF 사용 가능
    1. Kimera가 제공하는 중력 방향(gravity direction) 정보 이용

  • 핵심 인사이트

    → 천장 아래에서 3D ESDF를 수평 2D 단면으로 자르면, 방 안의 물체(clutter)의 영향을 거의 받지 않음

    • 이 2D 단면은 방 구조(layout)를 명확히 보여줌:
      • 대부분의 voxel 값 ≈ 0.3m (천장까지 거리)
      • 벽 근처 voxel 값 ≈ 0m (거리 감소)

      → 이 단면을 ESDF section이라고 부름 (천장 아래 0.3m 위치)

  • 노이즈 제거
    • ESDF section에서 0.2m 이하 거리를 잘라내어 방 사이의 작은 통로(openings) 제거

  • 방 분할 결과
    • 연결이 끊긴 2D ESDF들 → 각각의 방에 해당
    • Places 노드를 2D 수평 위치를 기준으로 방에 라벨링
    • 일부 장소는 라벨이 없음(벽 근처나 문 근처)
      • 다수결 투표(majority voting)로 반복 라벨링
    • Rooms-Places 연결
      • 각 장소(Layer 3) ↔ 해당 방(Layer 4) Edge 추가
      • 해당 방의 장소들이 연결되어 있으면 방도 연결(red edges)

A. Robustness of Mesh Reconstruction in Crowded Scenes
  • Kimera에 아래 기술들을 적용하여 VIO 강건성 향상
    • IMU-aware feature tracking
    • 2-point RANSAC

    → 추가적으로 dynamic masking을 결합하여 혼잡한 환경에서도 강건하고 정확한 metric-sementic mesh 생성

Enhanced VIO

  • 정량 평가 결과 (VIO error)
    • EuRoC 데이터셋 (정적 환경)
      • 기존 최고 성능 기법과 동등한 성능

        → 2-point RANSAC만 사용해도 성능 향상

    • uHumans 데이터셋 (동적 환경)

      → 제안 방법(DVIO)이 Kimera-VIO baseline 대비 압도적으로 우수

Dynamic Masking

  • dynamic masking 미적용 시:
    • 카메라 앞을 지나가는 사람이 mesh 위에 시안 색의 잔상(contrail)을 남기고 아티팩트 발생

  • dynamic masking 적용 시:
    • 깨끗한 mesh reconstruction 달성

  • 정량 평가 결과 (Mesh error)
    • GT 포즈 사용 시에도

      → 동적 객체로 인한 아티팩트가 mesh 정확도를 크게 저하시킴

    • dynamic masking

      → 위치 추정 정확도와 무관하게 mesh 품질을 크게 개선

B. Parsing Humans and Objects

Human Nodes

  • 정량적 결과 (localization error)
    • 구성
      • Single-img.: 단일 이미지 추정
      • Single-img. filtered: 부분적 가림(occlusion), 작은 bounding box 제거
      • Tracking(proposed): 제안한 pose graph 기반 추적

    • 결과
      • 인간이 가려지는 상황에서 오류 발생
      • 필터링으로 개선되지만 여전히 한계(가려짐) 존재
      • 제안한 Tracking 방식이 가장 정확하고 안정적인 Human Tracking 제공

Object Nodes

  • 정량적 결과 (localization error)
    • 구성
      • 요소
        • Known Shape, Unknown Shape Object 모두 평가
      • 위치 오차 (localization error)
        • 추정된 centroid와 GT centroid 간 거리
        • Know Shape Object는 CAD 모델의 centroid 사용
          • 위 결과에서는 “couch”라고 분류된 객체의 CAD 모델 사용
    • 결과
      • 두 경우 모두 객체 위치를 정확히 추정
      • CAD 모델이 있을 경우 정확도 추가 향상

C. Parsing Places and Rooms
  • 추출된 Places 및 Rooms 품질

  • 정량적 평가 (Classification)
    • 구성
      • 장소 → 방 분류 성능을 Precision / Recall로 평가
      • GT는 수동으로 장소를 방 단위로 분할하여 생성

DISCUSSION: QUERIES AND OPPORTUNITIES

여기서는 3D DSG의 활용 가능성을 보여준다.

Obstacle Avoidance and Planning
  • DSG에 포함된 agents, objects, rooms은 모두 bounding box 속성을 가진다.
  • 계층적 구조
    • 상위 레벨의 bounding box는, 하위 레벨의 bounding box를 포함

      (e.g. 방의 bounding box 안에 그 방에 있는 객체들이 포함됨)

    • Bounding Volume Hierarchy(BVH)를 형성

      → 컴퓨터 그래픽스 분야에서 충돌 검사(collision checking)에 널리 사용

  • BVH를 활용하면,
    • 충돌 검사를 핵심 연산으로 하는 장애물 회피 및 모션 플래닝을 훨씬 빠르게 수행할 수 있다.
    • 또한 DSG는 고수준 계획(high-level planning)에도 매우 유용하다.

      → DSG에서 장소와 객체의 연결된 부분 그래프를 이용해 로봇에게 “특정 객체를 찾아라(object search)”와 같은 고수준 명령을 내릴 수 있음

      → 로봇은 목표 객체와 가장 가까운 장소(place)를 DSG 상에서 바로 추론하고, 그 장소까지 도달하기 위한 실행 가능한 경로를 계획할 수 있음

또한 DSG가 제공하는 다중 추상화 레벨은 계층적(hierarchical)이고, 다중 해상도(multi-resolution) 계획 기법을 가능하게 하며, 이를 통해 연산 자원을 절약할 수 있다.

Human–Robot Interaction

이전 연구에서 보여줬듯이, Scene Graph는 아래와 같은 사용자 중심 작업을 지원한다.

  • 대화형 시각화
  • 질의응답(Question Answering)

제안하는 Dynamic Scene Graph는 이를 확장하여, human trajectory와 dense pose를 시각화할 수 있고, 시간을 고려한 복잡한 질의를 가능하게 한다.

  • 예시
    • “이 사람은 시각 t에 어디에 있었는가?”
    • “이 사람은 방 A에서 어떤 물체를 집었는가?”

또한 DSG는 agent와 환경 간의 개연성 있는 상호작용을 모델링하는 프레임워크를 제공하며, 자연어 기반 지시 해석(natural language grounding) 연구를 보완할 수 있다.

→ 이는 인간 지시의 다양성과 모호성을 추론하는 데 도움이 된다.

Long-term Autonomy

로봇의 장기 기억 관리 지원

  • DSG 계층 구조
    • 상위 레벨일수록 더 압축되고 추상적인 표현

      → 따라서 로봇은 자주 관측되지 않는 환경 정보를 해당 DSG branch(하위 노드 포함)를 제거(pruning)함으로써 “잊을(forget)” 수 있다.

      • 예시
        • 특정 방을 잊고 싶다면, 해당 방 노드 및 그 아래 연결된 장소, 객체 노드들을 함께 제거

로봇의 선택적 기억 유지

  • 저장 비용이 적은 객체 정보는 유지
  • 저장 비용이 큰 mesh 모델은 제거

기존 Scene Graph의 메모리 장점을 그대로 상속

  • 동일한 객체(e.g. N개의 의자들)가 있을 경우
    • CAD 모델은 하나만 저장
    • DSG 내 여러 노드에서 이를 참조

      → 데이터 압축 효과

Prediction
  • dense metric-sementic mesh 모델과 agent의 풍부한 설명을 결합

    → 단기적인 scene dynamics 예측 가능

    • 예를들어, mesh 모델을 물리 시뮬레이터에 입력하여, human agent의 가능한 고수준 행동을 시뮬레이션하고, 그에 따른 미래 상황에 대한 질의응답을 수행 가능

Conclusion

  • 3D Dynamic Scene Graphs(DSG)

    → Actionable한 공간 인식을 위한 통합 표현 방식

  • SPIN(Spatial PerceptIon eNgine)

    → 센서 데이터로부터 완전히 자동으로 DSG를 구축하는 최초의 공간 인식 엔진,

  • uHuman Dataset
    • Unity 기반 photorealistic simulator에서 수집한 데이터셋
    • SPIN의 성능을 입증 및 다양한 질의 가능성을 논의

      → 해당 질의 가능성에는 경로 계획, 인간-로봇 상호작용, 데이터 압축, 장면 예측이 포함

향후 연구 방향

  1. Section VI에서 제시된 질의들은 대부분 해결하기 쉽지 않은 연구 문제를 포함하고 있으며, 이에 대한 추가적인 심층 연구 필요
  1. DSG의 적용 범위 확장을 위해 더 많은 연구가 요구됨
    • 데이터로부터 추가적인 노드 속성을 추론하는 알고리즘

      e.g. 객체의 재질(material), 행동유도성(affordance)

    • 다른 환경에 맞는 새로운 노드 타입 설계

      e.g. 실외 환경

  1. SPIN의 시작 단계만을 다루었을 뿐이며, 여전히 많은 질문이 남아 있음
    • 다른 센서 조합에 특화된 SPIN을 설계하는 것에 이점이 있는가?
    • 실시간 및 점진적(incremental)으로 scene graph를 추정할 수 있는가?
    • 여러 로봇이 수집한 데이터를 이용해 분산(distributed) SPIN으로 하나의 DSG를 추정할 수 있는가?

느낀점

기존 3D Scene Graph의 한계점인 동적 객체 처리를 수행해냈고, 센서 데이터로부터 3D Dynamic Scene Graph를 완전히 자동으로 구축하는 공간 인식 엔진(SPIN)을 제안했다는 점이 새로웠다.

특히 human tracking을 진행할 때, 새로운 객체를 판단하는 과정에서 시간별 골격(skeleton)의 차이를 기반으로 consistency를 추정하거나, 물리적으로 가능한 관절의 움직임을 파악하는 것이 인상깊었다.

하지만 아래와 같이 몇 가지 의문점이 생겼다.

  • 개나 고양이와 같은 애완동물이나 로봇 청소기와 같이 인간과 다른 움직임을 가지는 동적 객체는 어떻게 처리할 수 있을까?
  • 만약 인간이 박스를 들고 이동할 때, 해당 박스는 동적 객체로 인지되는가?
  • 백화점에 서있는 마네킹은 사람으로 인식되어 동적 객체로 분류되는가?

위 의문점들과 함께, 결국 동적 객체에 대한 occlusion이 tracking의 가장 큰 한계라는 것을 깨달았다.

향후 계획

일단 해당 논문에서 핵심적으로 언급된 Kimera라는 모듈이 무엇인지 찾아볼 것 같다.

그리고 위 느낀점에서 언급했듯이 tracking 중에 발생하는 object occlusion에 대한 후속 연구가 있는지 살펴볼 것이다. 또한 해당 3D DSG가 실질적으로 응용된 사례가 있는지도 찾아볼 것 같다.
